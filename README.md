# Re-Forward — REINFORCE on STM32

Hardware-in-the-Loop (HIL) Reinforcement Learning: an STM32 microcontroller runs the full neural network and REINFORCE training loop, while the PC runs the Gymnasium environment and handles serial communication.

This branch targets a **NUCLEO-F446RE** (STM32F446RET6, Cortex-M4 @ 84 MHz); the port to the NUCLEO-H743ZI2 used by the `PPO` and `DQN` branches lives in `REINFORCE_H7`.

---

## Installation

### 1. Python (PC side)

Create the virtualenv **inside the `Micro_RL` folder**:

```bash
cd Micro_RL
python3 -m venv .venv
source .venv/bin/activate       # Linux/macOS
# or: .venv\Scripts\activate    # Windows

pip install -r requirements.txt
```

### 2. STM32 Firmware (microcontroller side)

**If you are using a NUCLEO-F446RE:**

Open the `tinyRL/` project directly in STM32CubeIDE — everything is already configured, just flash it.

**If you are using a different board:**

1. Create a new STM32CubeIDE project for your target.
2. Copy the following files into `Core/Src/` and `Core/Inc/`:
   - `dense_layer.c / .h`
   - `neural_net.c / .h`
   - `reinforce.c / .h`
   - `uart.c / .h`
   - `rng.c / .h`
   - `utils.c / .h`
   - `main.c` — **do not copy the whole file**: only copy the code inside the `USER CODE` blocks. Do not touch the init/clock functions generated by CubeMX.
3. Make sure USART2 is enabled at 115200 baud (or adapt `MX_USART2_UART_Init` and the `huart2` references to your peripheral).
4. Flash the firmware onto the board.

---

## Running

With the board connected via USB and the firmware flashed, launch the Python script:

```bash
cd Micro_RL
source .venv/bin/activate
python hil_trainer_continuous.py
```

Before running it, set the parameters at the top of the file:

| Parameter | Description |
|---|---|
| `PORT` | Serial port of the board (e.g. `/dev/ttyACM0`, `COM3`) |
| `BAUDRATE` | Must match the firmware value (default `115200`) |
| `USE_CONTINUOUS_ACTIONS` | `False` → discrete CartPole, `True` → continuous policy. Must match `USE_CONTINUOUS_ACTION` in `neural_net.h` |
| `ENV_NAME`, `OBS_DIM`, `ACTION_DIM` | Task configuration; must match `OBS_DIM` / `N_ACTIONS` (or `N_ACT_DIMS`) in `neural_net.h` |
| `TIME_LOG` | Must match `TIME_LOG` in `Core/Inc/main.h`; when enabled the board streams one timing row per update |

### Output files

Both are written to `Micro_RL/learning_curve_comparison/`:

- `training_reinforce_mcu.csv` — `episode, step, reward, episode_steps`, one row per episode.
- `mcu_timings.csv` — `episode, steps, total_ms, forward_ms, backward_ms, adam_ms`, one row per
  REINFORCE update (i.e. per episode), streamed live by the firmware when `TIME_LOG` is on.

## Firmware structure

| File | Role |
|---|---|
| [`Core/Src/main.c`](tinyRL/Core/Src/main.c) | Board init + HIL loop; defines the task (reward, termination, topology) |
| [`Core/Src/reinforce.c`](tinyRL/Core/Src/reinforce.c) | `ReinforceAgent`, episode buffer, discounted returns, `reinforce_update` |
| [`Core/Src/neural_net.c`](tinyRL/Core/Src/neural_net.c) | Generic `Network`: forward, backprop engine, Adam, gradient clipping, policy gradient |
| [`Core/Src/dense_layer.c`](tinyRL/Core/Src/dense_layer.c) | Dense layer allocation and Xavier init |
| [`Core/Src/uart.c`](tinyRL/Core/Src/uart.c) | Serial framing (STX + payload + XOR checksum + ETX) |
| [`Core/Src/rng.c`](tinyRL/Core/Src/rng.c) | PCG32 PRNG (action sampling, weight init) |
| [`Core/Src/utils.c`](tinyRL/Core/Src/utils.c) | DWT cycle counter helpers used for profiling |

The agent exposes the same high-level API as the `PPO` branch: `reinforce_agent_init()` receives
the reward function, the termination predicate and two optional callbacks
(`on_train_begin` / `on_train_end`), and the main loop only calls
`reinforce_step_discrete()` (or `reinforce_step()` in continuous mode).

## Configuring the task in the firmware

All user logic lives in the `USER CODE BEGIN 0` / `USER CODE BEGIN 2` / `USER CODE BEGIN WHILE`
blocks of [tinyRL/Core/Src/main.c](tinyRL/Core/Src/main.c).

### Reward and termination

```c
static float compute_reward(const float *obs, uint32_t act) {
    return 1.0f;   // CartPole: +1 for every non-terminal step
}

static uint8_t is_done(uint32_t step_in_ep) {
    if (step_in_ep >= MAX_STEPS_PER_EP)   return 1;   // 500-step truncation
    if (fabsf(s_cur_obs[0]) > CART_LIMIT) return 1;   // cart out of bounds
    if (fabsf(s_cur_obs[2]) > POLE_LIMIT) return 1;   // pole fell over
    return 0;
}
```

`s_cur_obs` holds the observation of the current step and is refreshed by the main loop right
before `reinforce_step_discrete()`, so `is_done()` can look at the state and not just the counter.

### Network topology

```c
int topology[]        = {OBS_DIM, 64, REINFORCE_POLICY_OUT_DIM};
ActivationType acts[] = {ACT_RELU, ACT_SOFTMAX};

network_init(&policy, sizeof(topology) / sizeof(topology[0]), topology, acts);
```

`topology` lists **every** layer size, input and output included; the second argument to
`network_init` is simply its length, so adding a hidden layer only means editing the two arrays.

### Hyperparameters

In [tinyRL/Core/Inc/neural_net.h](tinyRL/Core/Inc/neural_net.h) — network and action space:

```c
#define USE_CONTINUOUS_ACTION 0   // 0 = discrete softmax, 1 = diagonal Gaussian
#define N_ACTIONS   2             // discrete mode: number of actions
#define OBS_DIM     4             // observation size
#define N_ACT_DIMS  1             // continuous mode: number of action dims
```

In [tinyRL/Core/Inc/reinforce.h](tinyRL/Core/Inc/reinforce.h) — algorithm:

```c
#define REINFORCE_LR       0.01f
#define REINFORCE_GAMMA    0.99f
#define REINFORCE_ENT_COEF 0.001f
#define MAX_STEPS_PER_EP   500    // maximum episode length (= episode buffer size)
#define REINFORCE_SIGMA    0.5f   // continuous mode only: fixed std of the Gaussian
```

`USE_CONTINUOUS_ACTION` in `neural_net.h` must be the same value as `USE_CONTINUOUS_ACTIONS` in
`hil_trainer_continuous.py`, and `TIME_LOG` in `main.h` the same as `TIME_LOG` in the script.
