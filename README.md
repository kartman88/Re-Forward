# Re-Forward — PPO on STM32

Hardware-in-the-Loop (HIL) Reinforcement Learning: an STM32 microcontroller runs the full neural network and PPO training loop, while the PC runs the Gymnasium environment and handles serial communication.

---

## Installation

### 1. Python (PC side)

Create the virtualenv **inside the `Micro_RL` folder**:

```bash
cd Micro_RL
python3 -m venv .venv
source .venv/bin/activate       # Linux/macOS
# or: .venv\Scripts\activate    # Windows

pip install -r requirements.txt
```

### 2. STM32 Firmware (microcontroller side)

**If you are using a NUCLEO-F446RE:**

Open the `tinyRL/` project directly in STM32CubeIDE — everything is already configured, just flash it.

**If you are using a different board:**

1. Create a new STM32CubeIDE project for your target.
2. Copy the following files into `Core/Src/` and `Core/Inc/`:
   - `dense_layer.c / .h`
   - `neural_net.c / .h`
   - `reinforce.c / .h`
   - `utils.c / .h`
   - `main.c` — **do not copy the whole file**: only copy the code inside the `USER CODE` blocks. Do not touch the init/clock functions generated by CubeMX.
3. Make sure USART2 is enabled at 115200 baud (or adapt `MX_USART2_UART_Init` to your peripheral).
4. Flash the firmware onto the board.

---

## Running

With the board connected via USB and the firmware flashed, launch the Python script:

```bash
cd Micro_RL
source .venv/bin/activate
python hil_trainer_continuous.py
```

Before running it, set the parameters at the top of the file:

| Parameter | Description |
|---|---|
| `PORT` | Serial port of the board (e.g. `/dev/ttyACM0`, `COM3`) |
| `BAUDRATE` | Must match the firmware value (default `115200`) |
| `USE_CONTINUOUS_ACTIONS` | `False` → discrete CartPole, `True` → continuous Pendulum |
| `NET_TOPOLOGY` | Must match the topology defined in `main.c` (see below) |
| `DEBUG_MODE` | If `True`, saves debug data after the first episode to `debug_data/` |

## Configuring the neural network in the firmware

All user logic lives in the `USER CODE BEGIN 2` / `USER CODE BEGIN WHILE` blocks of [tinyRL/Core/Src/main.c](tinyRL/Core/Src/main.c).

### Network topology

```c
int input_size = 4;        // observation size (e.g. 4 for CartPole)

#if USE_CONTINUOUS_ACTIONS
  int output_size = 1;     // 1 output neuron (mu of the continuous policy)
  int net_topology[] = {input_size, 64, 64, output_size};
  ActivationType activations[] = {ACT_RELU, ACT_RELU, ACT_NONE};
#else
  int output_size = 2;     // 2 discrete actions
  int net_topology[] = {input_size, 64, output_size};
  ActivationType activations[] = {ACT_RELU, ACT_SOFTMAX};
#endif

int num_layers = 2;        // number of HIDDEN layers (does not count input or output)
init_network(&net, num_layers, net_topology, activations);
```

> **Note:** `num_layers` must equal the length of `net_topology` minus 2 (exclude the input and output layers). Update this value whenever you change the topology.

> **Note:** `NET_TOPOLOGY` in the Python script must exactly mirror `net_topology` in C (same number of layers, same sizes), otherwise the debug weight parsing will be incorrect.

### Hyperparameters (in [tinyRL/Core/Inc/neural_net.h](tinyRL/Core/Inc/neural_net.h))

```c
#define USE_CONTINUOUS_ACTIONS 0   // 0 = discrete, 1 = continuous (keep in sync with the Python script)
#define DEBUG 1                    // 1 = send debug data after the 1st episode

#define LR          0.0005f
#define GAMMA       0.99f
#define ENT_BETA    0.01f
#define MAX_STEPS   200            // maximum episode length
#define MAX_EPISODE 100            // maximum number of episodes
```

`USE_CONTINUOUS_ACTIONS` in `neural_net.h` must be the same value as `USE_CONTINUOUS_ACTIONS` in `hil_trainer_continuous.py`.
